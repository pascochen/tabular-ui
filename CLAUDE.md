# Tabular UI — project rules

Agentic ERP finance & ops data pipeline platform. Dense dashboards, admin panels, pipeline inspection, data-heavy screens.

Before changing tooling, dependencies, tests, package scripts, or deployment configuration, read `./tools.md` and follow it as the source of truth.

---

## Design system summary

- **Project**: Tabular UI — dense data tooling for finance and ops
- **Built on**: Tailwind CSS v4, OKLCH, CSS custom properties in `@theme`
- **Framework**: Vite + React
- **Palette**: Riso Ledger (2026-10-16) — seven OKLCH ramps on one shared lightness curve, all inside sRGB, generated by `packages/ui/scripts/generate-palette.mjs` into `packages/ui/src/styles/palette.css`. **Never hand-type a colour value.** Every Tailwind colour scale is stripped.
- **Neutral scale**: `ledger` — warm paper at the light end, blue-black ink at the dark end. It has one extra step, 925, for dark raised surfaces.
- **Brand assets**: the Tabular wordmark and favicon are brand marks drawn from the palette and are **outside the colour rules** (owner, 2026-10-22). Use them as files, unchanged, and derive nothing from them. See `docs/design-system.md` §1, "Brand assets".
- **Hues**: exactly five — sage, vermilion, ochre, federal, orchid. The accent is ink: the primary action, focus ring and checked controls are `ledger` (ink on paper, paper on ink in dark); the ring is a step softer, `ledger-800` / `ledger-200` (2026-10-22). Links and selection stay `sage`, the same green as success; federal is `info`. A seventh ramp, `teal`, is for chart series only.
- **Modes**: dark-first, light fully specified
- **Radius**: square. `--radius-xs` through `--radius-lg` are 0px since 2026-10-16; `--radius-full` keeps round shapes round (status dot, avatar, count badge, progress track). Every control is square, the switch included since 2026-10-23. Still name a rectangle's tier token, never `rounded-none` — see `docs/design-system.md` §7.7.
- **Components**: 18 foundational, 29 product — inventory in `docs/components.md`
- **Primitive layer**: shadcn/ui on **Base UI** — not Radix. Use `/docs/components/base/*`, never `/docs/components/radix/*`.
- **Icons**: `@phosphor-icons/react`, and nothing else. `lucide` and `hugeicons` are out of the stack. Stroke weight matches adjacent type weight, except at ≤16px where `bold` is the floor — see `docs/design-system.md` §11.
- **Package manager**: pnpm. All commands use `pnpm`, never `npm`.
- **Full spec**: `docs/design-system.md` — read it before writing any UI
- **Source of truth for values**: `packages/ui/src/styles/theme.css`, pointing at the generated ramps in `packages/ui/src/styles/palette.css`
- **Contrast**: `pnpm --filter tabular-ui contrast` measures every colour token on every ground it sits on, in both modes
- **Source of truth for rules and rationale**: `docs/design-system.md`
- **Figma is exploratory. `packages/ui/src/styles/theme.css` and `docs/design-system.md` are authoritative.** Sync flows code → Figma, never the reverse. A color picked by eye in Figma must never replace a measured OKLCH value.

When the CSS and the doc disagree, **the CSS wins on values, the doc wins on rules.** If you find a disagreement, say so rather than silently picking one.

## Non-negotiable rules

Violating any of these fails review.

1. **Color means state, never hierarchy.** Sidebar icons, table headers, section labels, secondary buttons, dividers: all neutral. A hue appears only when something is true about the data, the run, or the user's focus.
2. **Five hues. No sixth.** Never add a hue for a new feature. Compose from the five plus shape, weight, icon, or a neutral tint. `teal` is the palette's chart-only ramp, never a UI state.
3. **Never use 900/950 steps of chromatic scales as backgrounds.** They have hue-dependent lightness drift. Use `{hue}-500/10` over the canvas.
4. **Dark and light are not mirrors.** Foregrounds are chosen by OKLCH lightness, never by inverting the other mode's step index. Every Riso ramp shares one lightness curve, so every role's text is one step per mode: dark **step 400 (L 73)**, light **step 700 (L 46)**. The word "foregrounds" is load-bearing — solid *fills* sit at their own steps (dark fills are 600 because 700 is under 3:1 against the canvas; the light warning fill is `ochre-500`). See `docs/design-system.md` §0 rule 4, §2 and §4. *(Until 2026-10-16 this rule set lightness bands, L 66–71 dark and L 43–51 light, because Tailwind's ramps put each step at a different lightness per hue.)*
5. **Reach for the semantic layer first.** `--pad-cell-x` before `p-2`. `--color-text-danger` before `text-vermilion-400`.
6. **No component spacing above 32px, radius above 8px, control height above 36px.** The cap is the design. The page frame is the one exception: `--pad-frame-*`, capped at 64px, used only by `AppShell`, `EmptyState` and each workspace app's `App.tsx`. See `docs/design-system.md` §7.3 "Frame tier".
7. **All numbers carry `tabular-nums`.** Misaligned figure columns in a financial tool are a correctness hazard.
8. **Type in rem; spacing, radius and control heights in px.** Deliberate — see §7.5. Do not "fix" it to rem everywhere.
9. **`ledger-950` as canvas, never `#000`.** Pure black causes halation over multi-hour sessions.
10. **Never reference a raw hue in component code.** `federal-400` in a component breaks mode switching and any future hue change. Lint rejects every ramp name, Riso and Tailwind.

## Token naming convention

Pattern: `--color-{property}-{role}` for colors, `--{property}-{context}` for everything else.

**Property first, always.** This groups in autocomplete and matches Tailwind and CDS.

```
--color-text-primary   --color-text-danger    --color-text-interactive
--color-bg-danger      --color-border-agent   --color-fill-success
--color-on-warning     --pad-cell-x           --gap-bonded
```

**Colors must carry the `--color-` prefix.** In Tailwind v4, `--text-*` inside `@theme` is the font-size namespace. A color declared as `--text-danger` emits a *font-size* utility named `text-danger` — `class="text-danger"` would silently change the type size with no build error. `--text-*` belongs to the type scale in `docs/design-system.md` §8.1; colors live under `--color-*` per §4.

The generated utility names double the property word — `text-text-danger`, `bg-bg-danger`, `border-border-danger`. **This is expected. Do not "fix" it.** The short form requires role-first naming, which is rejected below. Full rationale and the utility table are in §4.

Roles: `interactive` · `danger` · `warning` · `success` · `agent` · `info`

Rejected — will not pass review:

- `--text-danger` for a color — collides with the font-size namespace
- `--danger-fg` — role first
- `--dangerText` — camelCase
- `--color-7`, `--bg-1` — meaningless
- `--red-text` — hue name instead of role; breaks the moment a hue changes
- `--space.md` — CSS custom properties cannot contain dots

## Components — two layers, opposite rules

This distinction matters more than any component list. Get it wrong and the system dies by a thousand inlined `<button>` elements.

### Foundational (18) — the contract

Adopted from shadcn/ui (Base UI variants) and restyled with our tokens. We do not author primitive behavior — focus trapping, roving tabindex, ARIA wiring are solved upstream. Our work is the token layer: `Button` is 32px because `--h-control` says so.

```
Button · IconButton · Input · Select · Combobox · Checkbox · Switch
Badge · Chip · Avatar · Tooltip · Menu · Popover · Dialog · Tabs
MessageScroller · Textarea · Spinner
```

Add via `pnpm dlx shadcn@latest add <component>`, then apply our tokens. Always pull the **Base UI** variant.

**Never create a new foundational component without asking.** Adding one is a system-level decision.

**Never re-implement a primitive inline.** If a table row needs a slightly different button, extend `Button` with a variant — do not inline a styled `<button>`. Two buttons that nobody knows about is how design systems fail.

Notes: `IconButton` is separate from `Button` — different padding, mandatory `aria-label`. `Tooltip` is not optional; truncated table cells are unreadable without it. There is no `Radio` — in dense UI a `Select` beats a radio group. `Avatar` (added 2026-10-07) is still by default; an `animatedSrc` plays only when asked and never under reduced motion. `MessageScroller` (added 2026-10-12) is shadcn's chat scroller: its behaviour is the headless `@shadcn/react` package, not Base UI, and it was written from source rather than `shadcn add` (see its README). `Textarea` (added 2026-10-13) is a native `<textarea>` styled as `Input`; it grows with its text, and one line is `--h-control`. `variant="borderless"` is for a field inside a container that draws its border and focus ring, as `ChatComposer` does. `Spinner` (added 2026-10-20) is the working indicator: a square tracer, the one mark drawn outside Phosphor (§11.5). It is shadcn's `Spinner` API with our glyph, written from source.

### Product (29) — domain composites

Built **from** foundational components. These should proliferate freely; that is what a product layer is for. Build them without asking, but check `docs/components.md` first.

```
Data display   DataTable · MetricTile · RunLogRow · LineageTree · CodeView · AttachmentRow · TruncatedText
Evidence       Sources · InlineCitation
Status         StatusBadge · ProgressBar · CountBadge
Controls       FilterChip · Toolbar · Field · ContextSwitcher · OrgSwitcher · ProjectSwitcher
Agent          AgentBlock · AgentReasoning · AgentPlan · Confirmation
Chat           ChatThread · ChatComposer · ChatStarter
Shell          AppShell · AppBar · AccountMenu · EmptyState
```

- `DataTable` — sortable, filterable, virtualized. 28px rows.
- `MetricTile` — KPI figure. `--font-display`, metric type tier, `tabular-nums`.
- `RunLogRow` — pipeline execution entry, 24px.
- `LineageTree` — nested dbt dependencies, 12px indent per level.
- `CodeView` — SQL and dbt models. Mono, one step below adjacent sans.
- `StatusBadge` — run and validation state. `--radius-xs`, tint bg, no border.
- `FilterChip` — interactive, dismissible. `--radius-md` (with every control, since 2026-10-15), border, hover state.
- `AgentBlock` — agent-authored content. Neutral box, solid orchid left rail, orchid authorship label. No ground, no icon (2026-10-14).

**`AgentBlock` is a category of one on purpose.** Agent-authored UI is a distinct class with its own constraints — orchid, left rail, mandatory authorship label. Do not build agent output as a generic `Card`; the authorship signal is the product's trust story and it disappears silently when someone reaches for the wrong primitive. `AgentReasoning`, `AgentPlan` and `Confirmation` are parts that sit **inside** an `AgentBlock` and draw no rail of their own: one block per agent turn, never one nested in another.

## Preferences

- **Observe before adding.** Before adding to an existing screen, read the surrounding components and think out loud about what you see: spacing density, which hues are in play, control heights, border usage. Match it. Do not invent a new pattern unless asked.
- Always reach for an existing component before creating a new one. When in doubt, ask.
- Product components compose from foundational ones. Never re-implement a primitive inline — extend it with a variant instead.
- kebab-case for tokens. PascalCase for components. camelCase for props.
- Co-locate stories and README with the component.
- Never use marketing words in product UI: "seamless", "unlock", "empower", "simply", "just", "easy".
- Focus rings use `outline` with `outline-offset`, never `box-shadow` — box-shadow rings get clipped by `overflow: hidden` on scrolling tables.
- Font weight never exceeds 600. At 13px on dark, 700 blooms and reduces legibility.
- Polarity color goes on variance and delta columns only, never on every number.

Mistakes recorded so they do not repeat. **Add to this list whenever a real mistake ships.** This is the only section that improves over time — keep it current.

Entries before 2026-10-23 were written when this was a single package, and keep the paths they were written with: `src/` is now `packages/ui/src/`, `scripts/generate-palette.mjs` and `scripts/check-contrast.mjs` are in `packages/ui/scripts/`, `tests/`, `.storybook/` and `scripts/visual-gate.mjs` are in `apps/storybook/`, `.storybook/a11y-exceptions.ts` is `packages/ui/src/fixtures/a11y-exceptions.ts`, and `apps/journey` is `apps/demo`. - Built a table with `p-3` instead of `--pad-cell-x`. Reach for the semantic layer first.
- Wrote a new `StatusBadge` rather than importing the existing one. Check `docs/components.md` first.
- Inlined a styled `<button>` inside a table row instead of extending `Button` with a variant. Never re-implement a primitive.
- Built an agent proposal panel as a generic `Card`. Agent-authored content uses `AgentBlock` — the authorship signal is not optional.
- Used a uniform `{hue}-400` for all five status foregrounds. They are not perceptually equal — the 400 step spans 6.34:1 to 12.89:1 on `neutral-950`. Use the lightness-matched steps in §2. *(True of Tailwind's ramps. Since Riso Ledger, 2026-10-16, every ramp shares one lightness curve and a uniform step per mode is the rule.)*
- Installed a shadcn component from the Radix docs path. We are on Base UI. Always use `/docs/components/base/*`.
- Followed a component link out of shadcn's `llms.txt`. Every link in it uses the bare `/docs/components/<name>` path, not `/base/`, and lands on whichever variant is currently default. Use `llms.txt` to learn that a component exists, then rewrite the URL to `/base/` yourself. See `tools.md`.
- Ran `npm install` in a pnpm repo, creating a second lockfile. Always `pnpm`.
- Wrote "colour is brand only" into an icon spec. There is no brand colour in this product's UI — colour means state (rule 1). The correct rule is that colour is never used *alone*: weight and shape carry the state too, so it survives grayscale. See §11.1.
- Pruned `@phosphor-icons/react` as an unused dependency because no source file imported it yet. `shadcn add` writes Phosphor imports without installing the package; removing it breaks the next vendored component. See `tools.md`.
- Declared a color under bare `--text-*` in `@theme`. That is Tailwind's font-size namespace; the color silently becomes a font size and nothing errors. Colors are `--color-text-*`. See §4.
- Measured light-mode contrast against `#fff` instead of the `neutral-50` canvas. Every ratio comes out ~4% optimistic. `--color-text-danger` is 4.56:1 on canvas, not 4.76:1, and clears AA by 0.06. Measure against `--color-canvas`.
- Invented `--color-bg-selected` and a per-role hover token. Selection uses `--color-bg-interactive`; hover and press use the single `--color-bg-hover` / `--color-bg-active` neutral overlay, which composites over any fill. *(Since 2026-10-16 the ink primary button takes the `-inverse` pair: the overlay is its own colour, so the shared one changed nothing.)* See §4.
- Referenced `var(--color-teal-400)` in the chart ramp. Chart hues are stripped to `initial` in §9 — the variable does not exist. Chart tokens hold literal OKLCH values, listed in §6.
- Imported `@fontsource-variable/inter` at its default entry point. That ships wght-only files and silently turns `font-optical-sizing: auto` into a no-op — import `/opsz.css`. Same class of failure as the Google Fonts URL in §9.
- Wrote a font stack naming `"JetBrains Mono"` when the installed package registers `"JetBrains Mono Variable"`. The stack fell through to `SF Mono` and rendered the wrong face with no error. Fontsource family names carry the `Variable` suffix.
- Paired `outline-none` with `focus-visible:outline-[length:…]` and shipped a focus ring that never painted. `outline-none` sets `--tw-outline-style: none`, and Tailwind's `outline-<length>` utility emits `outline-style: var(--tw-outline-style)` — so the style resolved back to `none` while width, offset and colour were all correct. Nothing errors, and every static check passes. Add `focus-visible:outline-solid`.
- Left shadcn's base `* { @apply outline-ring/50 }` in place. That wildcard beat every component's own `focus-visible` colour, so a `--color-ring` specified at full strength in §4 painted at 50% alpha everywhere. Only visible by reading the computed colour in a browser.
- Read design tokens in a Playwright test straight after `page.goto`. Storybook's decorator sets `data-theme` on render, not on load, so tokens resolve to the light `:root` defaults — every dark-mode assertion silently compared against light figures, and one test mixed a pre-switch canvas with a post-switch token. Wait for `data-theme` before reading anything.
- Assumed `outline` escapes `overflow: hidden`. It does not — an ancestor's overflow clips outlines exactly as it clips shadows, so swapping `box-shadow` for `outline` saves nothing by itself. What protects a ring is cell padding giving it room, or a **negative** `outline-offset` drawing it inside the element. Any control within ~3px of a scroll container's edge needs the inset form. See §4.
- Combined a custom `--text-*` size with a text colour in `cn()`. tailwind-merge only knows Tailwind's stock font sizes, so it read `text-metric` as a **colour** and dropped `text-text-primary` — a 32px KPI rendered in `--color-text-body` with no error. `src/lib/utils.ts` now teaches twMerge the whole §8.1 scale. Any size token added to the scale must be added there too.
- Fixed a table row's height with `h-[var(--h-row-sm)]` on the `<tr>` while cells carried `--pad-cell-y`. An 18px `StatusBadge` plus 6px+6px padding renders a 31px row; the virtualizer estimated 28 and scroll position drifted over 50k rows. Row height belongs on the **cell**, with `align-middle` — then text gets 6px and a badge 5px, which is §7.3's own arithmetic.
- Rendered a virtualized table inside an unbounded parent. The scroll container grows to the full table height, nothing scrolls, and the virtualizer renders every row — 50,000 `<tr>` in the DOM, no error, looks like virtualization is simply off. A windowed table's parent must have a bounded height.
- Assumed a Base UI `data-*` state attribute reflects the DOM. `Combobox`'s `data-empty` reflects Base UI's **collection**, not rendered children: render items by hand without passing `items` and the list is "empty" no matter how many rows are visible, so the empty-state message shows on top of a full list.
- Assumed Base UI uses one state attribute across components. It does not: Select items are `data-selected`, Tabs are `data-active`, Checkbox/Switch are `data-checked`, popup rows are `data-highlighted`. The wrong name compiles to a rule that simply never matches — no error, and in Tabs it silently left the active tab with no indicator and no text step at all.
- Wrote `data-active:` (Tailwind's shorthand) for a state that had to beat a base utility. The shorthand compiles inside `:where()`, which has **zero specificity**, so it ties with the plain class and loses on source order. Use the bracketed `data-[active]:` form, which emits a real attribute selector.
- Tried to override a token contextually by redefining `--color-border` on a container. §9's `@theme inline` **inlines** the reference, so `border-border` compiles to `border-color: var(--tui-border)` and the `--color-*` override is a silent no-op. Contextual overrides always target the `--tui-*` layer.
- Used `--color-border` for a divider inside a popup. §3 gives `--color-border` and `--color-surface-raised` the same value in dark mode (both `neutral-800`), so the line is invisible — and light mode hides it, because there the raised surface is `#fff`. Dividers and bordered controls on a raised ground take `--color-border-strong`; `popupSurface` now does this for its whole subtree. *(Since Riso Ledger the two differ, but `--color-border` on the raised surface is still only 1.60:1 dark and 1.29:1 light, so the rule stands.)*
- Put a context provider on `SelectTrigger` to share a prop with `SelectItem`. In a compound component the parts are **siblings**, not descendants — a provider on one part reaches none of the others. It belongs on the root. The symptom was silent: items simply rendered in the default face, with no error.
- Let a browser-mode test suite discover a new Base UI dependency mid-run. Vite optimizes it and reloads the page underneath in-flight tests, so the newest story file fails once and passes on retry — flakiness that looks like a bad test. Add each new Base UI entry point to `optimizeDeps.include` in `vite.config.ts`.
- Assumed a `Tooltip` announces its text to screen readers. Base UI's tooltip is visual only — no `id`, no `role`, no `aria-describedby` on the trigger. Never put information in a tooltip that exists nowhere else; the accessible name must come from `aria-label` or visible text. See `Tooltip/README.md`.
- Used `--gap-icon-label` (2px) for the icon gap in a `Button`. That token is scoped to badges and chips, where the icon and label are one atomic mark. In a control the gap must exceed the font's word space (3.46px at `--text-base` in Inter, 2.60px in Source Sans 3) or the icon binds to the first word more tightly than the words bind to each other. Controls use `--gap-control-icon` (6px). See §7.4.
- Wrote `has-[>svg:last-child]:pr-1.5` to detect a trailing icon. `:last-child` counts **element** children only, so an icon followed by a bare text label matches both `:first-child` and `:last-child` and both paddings collapse. CSS cannot see text nodes — detect edge icons in React.
- Rendered a dbt model name in `--font-mono` at the same size as the surrounding sans. Mono runs visually larger at equal px, so §8.3 sets it one step below — in a `--text-sm` row, identifiers are `--text-xs`. Caught in review of the first `Button` story.
- Declared a `--text-*` size without its `--text-*--line-height` partner. The size then inherits whatever line-height is in scope, which is the difference between a 28px and a 32px table row.
- Reached for Base UI's `Button` with `render={<a/>}` to style a navigation link. `useButton` merges `type="button"` when `nativeButton` is true — and logs a dev-only error if the element is not a `<button>` — or **`role="button"`** when it is false, which makes a screen reader announce the link as a button and lose its navigation semantics. Nothing fails in CI either way. A link needs no behavior polyfill; share only the appearance, via the exported `buttonVariants` cva on a real `<a>`. See `AppBar`.
- Documented a component's height as the sum of its padding and content. A 1px `border-b` counts in the border box, so the measured band was 49px, not 48. Measure the rendered box before writing a geometry number into a README.
- Paired a styled `Button` with a visually-hidden `<input type="file">` and shipped **two** controls named "Choose file". Chrome exposes a bare file input as its own button with that default accessible name, so a screen reader announces it twice and the tab order stops on an invisible element. `sr-only` hides it visually, not from AT. The input needs `aria-hidden="true"` **and** `tabIndex={-1}` — the second is what makes the first legitimate. Caught by a Playwright strict-mode violation, not by lint or the a11y addon. See `AttachmentRow`'s `UploadTarget` story.
- Resolved a component from a lookup **function** during render (`const Glyph = iconForFile(name)`). React Compiler rejects it (`react-hooks/static-components`): a function returning a component yields a fresh identity each render, which remounts the subtree. Indexing a module-level map is fine — that is what `StatusBadge` does with `runStatuses`. Export the map and a string helper, never a `getComponent()`.
- Reached for a stretched `absolute inset-0` trigger to make a row wholly clickable. It makes the row's text unselectable, because the overlay eats the pointer — and in this product filenames, GL references and model names are copied constantly.
