# Tabular UI — project rules

Agentic ERP finance & ops data pipeline platform. Dense dashboards, admin panels, pipeline inspection, data-heavy screens.

Before changing tooling, dependencies, tests, package scripts, or deployment configuration, read `./tools.md` and follow it as the source of truth.

---

## Design system summary

- **Project**: Tabular UI — dense data tooling for finance and ops
- **Built on**: Tailwind CSS v4, OKLCH, CSS custom properties in `@theme`
- **Framework**: Vite + React
- **Palette**: Riso Ledger (2026-10-16) — seven OKLCH ramps on one shared lightness curve, all inside sRGB, generated by `packages/ui/scripts/generate-palette.mjs` into `packages/ui/src/styles/palette.css`. **Never hand-type a colour value.** Every Tailwind colour scale is stripped.
- **Neutral scale**: `ledger` — warm paper at the light end, blue-black ink at the dark end. It has one extra step, 925, for dark raised surfaces.
- **Brand assets**: the Tabular wordmark and favicon are brand marks drawn from the palette and are **outside the colour rules** (owner, 2026-10-22). Use them as files, unchanged, and derive nothing from them. See `docs/design-system.md` §1, "Brand assets".
- **Hues**: exactly five — ivy, vermilion, ochre, lake, orchid. The accent is ink: the primary action, focus ring and checked controls are `ledger` (ink on paper, paper on ink in dark); the ring is a step softer, `ledger-800` / `ledger-200` (2026-10-22). Links are ink too, underlined, since 2026-11-09. Selection stays `ivy` (`sage` until 2026-11-03; `--color-sage-*` is a deprecated alias), the same green as success; `lake` is `info` (`federal` until 2026-11-06; `--color-federal-*` is a deprecated alias). A seventh ramp, `teal`, is for chart series only.
- **Modes**: dark-first, light fully specified
- **Radius**: square. `--radius-xs` through `--radius-lg` are 0px since 2026-10-16; `--radius-full` keeps round shapes round (status dot, avatar, count badge, progress track). Every control is square except the switch, which is round again since 2026-11-10 (it was square from 2026-10-23). Still name a rectangle's tier token, never `rounded-none` — see `docs/design-system.md` §7.7.
- **Components**: 18 foundational, 34 product — inventory in `docs/components.md`
- **Primitive layer**: shadcn/ui on **Base UI** — not Radix. Use `/docs/components/base/*`, never `/docs/components/radix/*`.
- **Icons**: `@phosphor-icons/react`, and nothing else. `lucide` and `hugeicons` are out of the stack. Stroke weight matches adjacent type weight, except at ≤16px where `bold` is the floor — see `docs/design-system.md` §11.
- **Package manager**: pnpm. All commands use `pnpm`, never `npm`.
- **Full spec**: `docs/design-system.md` — read it before writing any UI
- **Source of truth for values**: `packages/ui/src/styles/theme.css`, pointing at the generated ramps in `packages/ui/src/styles/palette.css`
- **Contrast**: `pnpm --filter tabular-ui contrast` measures every colour token on every ground it sits on, in both modes
- **Source of truth for rules and rationale**: `docs/design-system.md`
- **Figma is exploratory. `packages/ui/src/styles/theme.css` and `docs/design-system.md` are authoritative.** Sync flows code → Figma, never the reverse. A color picked by eye in Figma must never replace a measured OKLCH value.

When the CSS and the doc disagree, **the CSS wins on values, the doc wins on rules.** If you find a disagreement, say so rather than silently picking one.

## Non-negotiable rules

Violating any of these fails review.

1. **Color means state, never hierarchy.** Sidebar icons, table headers, section labels, secondary buttons, dividers: all neutral. A hue appears only when something is true about the data, the run, or the user's focus.
2. **Five hues. No sixth.** Never add a hue for a new feature. Compose from the five plus shape, weight, icon, or a neutral tint. `teal` is the palette's chart-only ramp, never a UI state.
3. **Never use 900/950 steps of chromatic scales as backgrounds.** They have hue-dependent lightness drift. Use `{hue}-500/10` over the canvas.
4. **Dark and light are not mirrors.** Foregrounds are chosen by OKLCH lightness, never by inverting the other mode's step index. Every Riso ramp shares one lightness curve, so every role's text is one step per mode: dark **step 400 (L 73)**, light **step 700 (L 46)**. The word "foregrounds" is load-bearing — solid *fills* sit at their own steps (dark fills are 600 because 700 is under 3:1 against the canvas; the light warning fill is `ochre-500`). See `docs/design-system.md` §0 rule 4, §2 and §4. *(Until 2026-10-16 this rule set lightness bands, L 66–71 dark and L 43–51 light, because Tailwind's ramps put each step at a different lightness per hue.)*
5. **Reach for the semantic layer first.** `--pad-cell-x` before `p-2`. `--color-text-danger` before `text-vermilion-400`.
6. **No component spacing above 32px, radius above 8px, control height above 36px.** The cap is the design. The page frame is the one exception: `--pad-frame-*`, capped at 64px, used only by `AppShell`, `EmptyState` and each workspace app's `App.tsx`. See `docs/design-system.md` §7.3 "Frame tier".
7. **All numbers carry `tabular-nums`.** Misaligned figure columns in a financial tool are a correctness hazard.
8. **Type in rem; spacing, radius and control heights in px.** Deliberate — see §7.5. Do not "fix" it to rem everywhere. Since 2026-11-10 a control or row height yields once its own line of text no longer fits (`max(32px, 1.25rem + 4px)`, §7.6), and an avatar is sized in rem. Nothing else follows the type, and nothing changes at the default text size.
9. **`ledger-950` as canvas, never `#000`.** Pure black causes halation over multi-hour sessions.
10. **Never reference a raw hue in component code.** `lake-400` in a component breaks mode switching and any future hue change. Lint rejects every ramp name, Riso and Tailwind.

## Token naming convention

Pattern: `--color-{property}-{role}` for colors, `--{property}-{context}` for everything else.

**Property first, always.** This groups in autocomplete and matches Tailwind and CDS.

```
--color-text-primary   --color-text-danger    --color-text-interactive
--color-bg-danger      --color-border-agent   --color-fill-success
--color-on-warning     --pad-cell-x           --gap-bonded
```

**Colors must carry the `--color-` prefix.** In Tailwind v4, `--text-*` inside `@theme` is the font-size namespace. A color declared as `--text-danger` emits a *font-size* utility named `text-danger` — `class="text-danger"` would silently change the type size with no build error. `--text-*` belongs to the type scale in `docs/design-system.md` §8.1; colors live under `--color-*` per §4.

The generated utility names double the property word — `text-text-danger`, `bg-bg-danger`, `border-border-danger`. **This is expected. Do not "fix" it.** The short form requires role-first naming, which is rejected below. Full rationale and the utility table are in §4.

Roles: `interactive` · `danger` · `warning` · `success` · `agent` · `info`

Rejected — will not pass review:

- `--text-danger` for a color — collides with the font-size namespace
- `--danger-fg` — role first
- `--dangerText` — camelCase
- `--color-7`, `--bg-1` — meaningless
- `--red-text` — hue name instead of role; breaks the moment a hue changes
- `--space.md` — CSS custom properties cannot contain dots

## Components — two layers, opposite rules

This distinction matters more than any component list. Get it wrong and the system dies by a thousand inlined `<button>` elements.

### Foundational (18) — the contract

Adopted from shadcn/ui (Base UI variants) and restyled with our tokens. We do not author primitive behavior — focus trapping, roving tabindex, ARIA wiring are solved upstream. Our work is the token layer: `Button` is 32px because `--h-control` says so.

```
Button · IconButton · Input · Select · Combobox · Checkbox · Switch
Badge · Chip · Avatar · Tooltip · Menu · Popover · Dialog · Tabs
MessageScroller · Textarea · Spinner
```

Add via `pnpm dlx shadcn@latest add <component>`, then apply our tokens. Always pull the **Base UI** variant.

**Never create a new foundational component without asking.** Adding one is a system-level decision.

**Never re-implement a primitive inline.** If a table row needs a slightly different button, extend `Button` with a variant — do not inline a styled `<button>`. Two buttons that nobody knows about is how design systems fail.

Notes: `IconButton` is separate from `Button` — different padding, mandatory `aria-label`. `Tooltip` is not optional; truncated table cells are unreadable without it. There is no `Radio` — in dense UI a `Select` beats a radio group. `Avatar` (added 2026-10-07) is still by default; an `animatedSrc` plays only when asked and never under reduced motion. `MessageScroller` (added 2026-10-12) is shadcn's chat scroller: its behaviour is the headless `@shadcn/react` package, not Base UI, and it was written from source rather than `shadcn add` (see its README). `Textarea` (added 2026-10-13) is a native `<textarea>` styled as `Input`; it grows with its text, and one line is `--h-control`. `variant="borderless"` is for a field inside a container that draws its border and focus ring, as `ChatComposer` does. `Spinner` (added 2026-10-20) is the working indicator: a square tracer, the one mark drawn outside Phosphor (§11.5). It is shadcn's `Spinner` API with our glyph, written from source.

### Product (34) — domain composites

Built **from** foundational components. These should proliferate freely; that is what a product layer is for. Build them without asking, but check `docs/components.md` first.

```
Data display   DataTable · MetricTile · RunLogRow · LineageTree · CodeView · AttachmentRow · TruncatedText
Evidence       Sources · InlineCitation
Status         StatusBadge · StatusDot · ProgressBar · CountBadge
Controls       FilterChip · Toolbar · Field · ContextSwitcher · OrgSwitcher · ProjectSwitcher
Agent          AgentBlock · AgentReasoning · AgentPlan · Confirmation · Question · Tool
Chat           ChatThread · ChatComposer · ChatStarter · ChannelMessage · PresenceStack
Shell          AppShell · AppBar · AccountMenu · EmptyState
```

- `DataTable` — sortable, filterable, virtualized. 28px rows. Its totals row draws the double rule only when the rows on display sum to the stated total: no prop sets it (§7.8).
- `MetricTile` — KPI figure. `--font-display`, metric type tier, `tabular-nums`.
- `RunLogRow` — pipeline execution entry, 24px.
- `LineageTree` — nested dbt dependencies, 12px indent per level.
- `CodeView` — SQL and dbt models. Mono, one step below adjacent sans.
- `StatusBadge` — run and validation state. `--radius-xs`, tint bg, no border.
- `StatusDot` — §7.7's 6px dot. Solid ochre when it waits on the viewer, a hollow ring when it doesn't (§5).
- `FilterChip` — interactive, dismissible. `--radius-md` (with every control, since 2026-10-15), border, hover state.
- `AgentBlock` — agent-authored content. Neutral box, solid orchid left rail, orchid authorship label. No ground, no icon (2026-10-14).

**`AgentBlock` is a category of one on purpose.** Agent-authored UI is a distinct class with its own constraints — orchid, left rail, mandatory authorship label. Do not build agent output as a generic `Card`; the authorship signal is the product's trust story and it disappears silently when someone reaches for the wrong primitive. `AgentReasoning`, `AgentPlan`, `Confirmation`, `Question` and `Tool` are parts that sit **inside** an `AgentBlock` and draw no rail of their own: one block per agent turn, never one nested in another.

## Preferences

- **Observe before adding.** Before adding to an existing screen, read the surrounding components and think out loud about what you see: spacing density, which hues are in play, control heights, border usage. Match it. Do not invent a new pattern unless asked.
- Always reach for an existing component before creating a new one. When in doubt, ask.
- Product components compose from foundational ones. Never re-implement a primitive inline — extend it with a variant instead.
- kebab-case for tokens. PascalCase for components. camelCase for props.
- Co-locate stories and README with the component.
- Never use marketing words in product UI: "seamless", "unlock", "empower", "simply", "just", "easy".
- Focus rings use `outline` with `outline-offset`, never `box-shadow` — box-shadow rings get clipped by `overflow: hidden` on scrolling tables.
- Font weight never exceeds 600. At 13px on dark, 700 blooms and reduces legibility.
- Polarity color goes on variance and delta columns only, never on every number.

### Colour, tokens and type

- Never add a sixth hue. Compose from the five plus shape, weight, icon or a neutral tint.
- Never use a chromatic 900/950 step as a background. Use `{hue}-500/10` over the canvas.
- Colour is never used alone: weight and shape carry the state too. There is no brand colour in the UI.
- Display tracking is 0. Never apply `--tracking-tight` to the metric tier.
- Reach for the semantic layer first: `--pad-cell-x` before `p-3`.
- A colour token is `--color-text-*`. Bare `--text-*` in `@theme` is a font size, and nothing errors.
- Measure contrast against the ground the text sits on: the canvas, not `#fff`, and a surface, not the canvas. §3's ratios are on the canvas.
- No `--color-bg-selected` and no per-role hover token. Selection is `--color-bg-interactive`; hover and press are the one neutral overlay.
- `--color-text-tertiary` is for placeholders, disabled labels and non-text marks. Anything a user reads is `--color-text-secondary`.
- A contextual token override targets the `--tui-*` layer. `@theme inline` inlines `--color-*`, so overriding that is a silent no-op.
- On a raised ground, dividers and bordered controls take `--color-border-strong`. `popupSurface` does it for its subtree.
- When the art direction changes, list every value that draws an edge (borders, rings, shadows, masks) and re-measure each on its ground.
- Load a variable font from the entry point that carries its axes (`opsz.css`). The default ships weight only and silently turns optical sizing off.
- A Fontsource variable family's name ends in `Variable`. A stack without it falls through to the next font with no error.
- Set the display tier with the `font-display` class, never `var(--font-display)`: a family's partner settings ride on the utility.
- A property that belongs to a font family rides on the family token's partner (`--font-mono--font-feature-settings`), never on each call site. Held by `mono-features.spec.ts`.
- Mono is one step below the adjacent sans: `--text-xs` in a `--text-sm` row.
- Every `--text-*` size is declared with its `--text-*--line-height` partner.
- A size added to §8.1's scale is added to twMerge's config in `src/lib/utils.ts` too, or `cn()` reads it as a colour and drops the text colour.
- A `ch` is the width of "0", not of a character. In Instrument Sans, N characters are about 0.67×N `ch` (§8.3).
- When Tailwind adds a colour scale, add it to §9's strip list and to `lint/palette.mjs`. Held by `palette.spec.ts`.

### Tailwind and CSS

- `outline-none` beside an `outline-[length:…]` utility paints no ring. Add `outline-solid` under the same variant, whatever it is (`focus-visible:`, `focus-within:`, `data-[…]:`). Nothing checks the pairing in general.
- `truncate` does nothing on a `display: flex` element. Put it on a block child. shadcn's parts are `flex` by default, so check vendored code first.
- A transparent border is still geometry. A label that lines up with a `Button`'s text needs the border as well as the padding, and a 2px inset beside a 1px border is 3px. Held by `app-shell.spec.ts`, `switch.spec.ts`.
- Measure a rendered box before writing its size in a README: a 1px border counts.
- Remove shadcn's base `* { @apply outline-ring/50 }`. It halves every focus ring's colour.
- `outline` does not escape `overflow: hidden`. Within about 3px of a scroll container's edge, draw the ring inside with a negative `outline-offset`.
- For a state that must beat a base utility, write `data-[active]:`, not `data-active:`. The shorthand has zero specificity.
- CSS cannot see text nodes: `:last-child` counts elements only. Detect an edge icon in React.
- `sr-only` with `buttonVariants` stays in flow, because its `relative` wins. Use `fixed`.
- `Button` carries `shrink-0`. To let one truncate, add `shrink` as well as `min-w-0`.
- An exported cva other than `buttonVariants` returns a bare string. Pass it through `cn()`, or two conflicting classes both apply.
- A `<button>` does not inherit `text-transform`. A control whose text follows its context sets it, and a test asserts the computed style.
- Opacity compounds. A container that fades its contents cancels the fade on any child that fades itself. Held by `chat-panel.spec.ts`.
- A variant that matches nothing raises no error: `group-hover:` needs `.group`, and `Button`'s group is `group/button`. A column's alignment rule covers its header too, on both axes. Held by `density.spec.ts`.
- Never restate a token's px value as a number literal. Read it at runtime (`popupRowInset()`), and assert token-derived geometry exactly, not with `>=`.
- In a control, the icon gap is `--gap-control-icon` (6px). `--gap-icon-label` (2px) is for badges and chips.

### Base UI, shadcn and React

- Install shadcn components from `/docs/components/base/*`. Links in `llms.txt` use the bare path: rewrite them.
- Keep `@phosphor-icons/react` even when nothing imports it: `shadcn add` writes Phosphor imports without installing the package.
- A Base UI `data-*` state reflects its collection, not the DOM. Pass `items`, or `data-empty` stays true over a full list.
- Base UI's state attributes differ by component: `data-selected` (Select), `data-active` (Tabs), `data-checked` (Checkbox, Switch), `data-highlighted` (popup rows). A wrong name never matches and never errors.
- Style disabled on `data-[disabled]` as well as `disabled:`: Base UI parts often lack the native attribute. When a shared contract misses a state, fix the contract, not the call site. Held by `disabled-controls.spec.ts`.
- A wrapper that reads a primitive's prop for its own styling still forwards it. Held by `tabs.spec.ts`.
- In a compound component, a context provider goes on the root. The parts are siblings.
- Style a navigation link with `buttonVariants` on a real `<a>`, never Base UI's `Button` with `render={<a/>}`.
- Add each new Base UI entry point to `optimizeDeps.include`, or the browser test suite reloads mid-run and looks flaky.
- Never resolve a component from a function during render. Index a module-level map.
- A module augmentation lives in the module that owns it, so it travels with the import graph.
- A value one effect consumes and another may overwrite is read once into state before any effect runs.
- Open a hover affordance on a real `pointermove`, not `pointerenter`. A test that something did not open first waits for the event that would have opened it.

### Components and layout

- Check `docs/components.md` before building, and import the component that exists.
- Never hand-style a `<button>` outside foundational, by literal tag or through a variable. Extend `Button` with a variant. Held by lint.
- Agent-authored content is an `AgentBlock`, never a generic card.
- A rule a component can enforce belongs in the component, not in its README: `Button` sets its icon weight, and `controlBase` draws disabled icons `light`. Held by `icon-weight.spec.ts`.
- A prop never reuses the name of a DOM attribute the element could need: `tone`, not `role`. Held by lint.
- Name a variant after §1's role (`danger`), never a synonym. Held by lint.
- A table row's height goes on the cell, with `align-middle`, not on the `<tr>`.
- A virtualized table's parent has a bounded height, or every row renders.
- Whole-row activation is `DataTable`'s `onRowClick`, never a stretched overlay, and a drag that selects text must not open the row. Held by `data-table-selection.spec.ts`.
- What a figure looks like and what leaves the screen are separate claims. In anything people copy, test the clipboard. Held by `data-table-copy.spec.ts`, `identifier-copy.spec.ts`.
- A default written for text is checked against everything else a cell holds: a figure never truncates and a badge keeps its width. Truncated text needs a way to be read, and a tooltip never opens on touch. Held by `density.spec.ts`.
- A shared treatment needs a check in every consumer, and a computed border is not a painted one: a `<tr>` in a `border-separate` table paints none. Held by `density.spec.ts`.
- A popup list that can overflow needs an explicit cue (Select's arrows, Combobox's edge mask). A fixed `max-h` cannot guarantee a partial row.
- A fallback that states a fact, such as a direction or a status, is a guess. When the input is missing, render nothing, and a check that has not run is neither passed nor failed.
- A shell band is 49px only if its child is at least `--h-control` tall. Measure both rules in the app, not only in the story.
- A client-rendered view lands its own URL fragment on mount. Test a link by loading it from another URL.
- A scroll that runs on mount runs on every mount. Check it on each way into the view.

### Accessibility

- A `Tooltip` is visual only. Never put information in one that exists nowhere else: the name comes from `aria-label` or visible text.
- A visually hidden file input beside a styled `Button` needs `aria-hidden="true"` and `tabIndex={-1}`, or it is announced twice.
- A render prop that promises the wiring carries every attribute it promises: `required` and `aria-required`. Held by `Field`'s `WithError` story.
- A composite ARIA role (`tree`, `grid`, `listbox`, `menu`) promises its keyboard pattern. Implement and test it, or use plain structure.
- A live region holds its announcement briefly, then empties. Text left in it is read twice.
- When an accessibility attribute depends on a client-only measure, the server's default is the accessible one. Held by `code-view.spec.ts`.
- A rule about the page cannot fail on a fragment. Run `region` where the page is assembled. Held by `app-shell.spec.ts`.
- A clean axe run covers only the rules that ran. For a claim a comment makes, run the rule by name. Held by `account-menu.spec.ts`.
- A mark drawn only by `background` is gone in forced colours, whatever its size.
- Storybook's a11y test mode stays `'error'`. A story that cannot pass takes a named exception that turns off one rule.
- A view people use and no test covers is unverified: check Storybook's Docs pages in dark mode too. Held by `docs-pages.spec.ts`.

### Tests

- In Playwright, wait for `data-theme` before reading a token. `gotoStory` does.
- Measure after the fonts load, which `gotoStory` waits for. To test a timing theory, delay the one resource it blames.
- A test on a story's page shares globals with addons still running. Run axe only once the render is `finished`, as `injectAxe` does.
- A story ends in a still state before its screenshot: no typing in flight, a jump in place of a smooth scroll under `navigator.webdriver`, and text a play function changes keeps its first glyph.
- A fake clock removes real time only from the moment it stops. Stop it before what it times begins: a margin does not close a race.
- Assert a visual truncation on the visible node's `textContent`, never `innerText`, which includes `sr-only` text.
- `getComputedStyle` returns `oklch`, `oklab` or `rgb`, with chroma in a different slot in each. Parse all three.
- Set a story's viewport with `globals: { viewport: { value } }`. The Storybook 8 form is ignored silently.
- A regex lint gate fails open. Probe each new rule through `eslint --stdin`, bracketed forms included.
- A gate that claims "every" iterates the declarations, not the checks. Held by `check-contrast.mjs`.
- Quote globs in any check whose success is silence (zsh expands them first), and treat an error line in a clean result as a failed check.
- A flaky-test fix needs a failure signature that predicts which runs fail, then a count of the runs since. A watchdog starts its timer on something the stalled side cannot withhold.

### CI, tooling and the repository

- `pnpm`, never `npm`.
- Never point `STORYBOOK_PORT` at a port another checkout may hold. The port is derived from the checkout's path.
- Never write GitHub's skip-CI token in a commit message, even to describe it: a squash merge carries it to `main`.
- No machine paths in committed config. Name the tool and let `PATH` find it.
- A clean-clone check runs the commands in CI's order, from a checkout nothing has built in.
- A CI skip that depends on a fact about the code needs a test of that fact. Held by `ci-scope.spec.ts`.
- A step that vouches for a run counts only steps that have finished.
- Never put a PR's screenshots on an orphan branch: Vercel builds every branch. Use a tag, or a raw URL at a commit SHA.
- When a screen changes, look in `public/` for pictures of it. The demo's `og.png` is rewritten by a script.
- Record the Chrome and Lighthouse versions and how the build was served beside every score, and compare two builds in one session.

### Specs, proposals and docs

- Before proposing a token change, read §0 and search the spec for the step being replaced. A rule or lock it touches goes in the proposal's first lines.
- A spec's examples get copied more than its rules get read. Check each example against the spec's own scope.
- A placeholder in a story is a stand-in, not a decision. Benchmark the pattern before building on it.
